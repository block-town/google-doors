# Google Doors

Claude Code в вашем Google Workspace: Gmail, Drive, Calendar, Docs, Sheets, Slides, Forms, Tasks, Contacts, Apps Script и Google Analytics, через MCP-серверы, которые работают на вашем компьютере с вашим собственным клиентом Google.

Из приложения Claude коннекторы Anthropic уже открывают три двери: Gmail, Calendar и Drive, а Docs, Sheets и Slides теперь в бете. Этот репозиторий открывает для Claude Code все двери. В [docs/00-what-claude-already-has.md](docs/00-what-claude-already-has.md) точно сказано, что умеют коннекторы и что добавляет kit. Прочитайте это первым: если открытых дверей хватает, здесь вам ничего не нужно.

Публикует Sam Town, [samuel.town](https://samuel.town). Пользоваться, копировать и менять можно свободно по лицензии MIT: см. [LICENSE](LICENSE).

Эта страница переведена с английского с помощью ИИ. Если формулировка звучит неловко или неточно, напишите в issue или пришлите pull request. Основной текст: [README.md](README.md); перевод соответствует его версии из того же коммита, что и эта страница. Остальные страницы руководства пока только на английском.

Названия кнопок и разделов Google даны по-английски, как в англоязычном интерфейсе. Если консоль Google у вас на русском, подписи будут переведены.

## Что это

Два сервера и kit, которые работают вместе:

- **Сервер Workspace**, [workspace-mcp](https://github.com/taylorwilsdon/google_workspace_mcp) Тейлора Уилсдона (Taylor Wilsdon), лицензия MIT, закреплён на версии 2.0.1, самой свежей на PyPI на 2026-10-05. Он работает на вашем компьютере и даёт Claude Code набор инструментов: искать письма, править документ, заполнять таблицу, отвечать на комментарий, ставить встречу. С десятью сервисами, которые kit подключает по умолчанию, это 112 инструментов (подсчёт от 2026-10-05).
- **Сервер Analytics**, собственный [analytics-mcp](https://github.com/googleanalytics/google-analytics-mcp) от Google (Apache 2.0; Google помечает его как «Experimental»), закреплён на версии 0.7.0. Он читает ваши отчёты Google Analytics и ничего не меняет. На 2026-10-05 у него 9 инструментов.
- **Kit**: скрипты на Python и руководство. `./setup` ставит оба сервера, хранит ваш клиент в файле, который можете читать только вы, и добавляет оба сервера в Claude Code. `./auth` выполняет вход в Google; `./auth-analytics` добавляет отдельный вход только на чтение для Analytics. `./doctor` делает по одному вызову на чтение в каждый сервис Google и называет, чего не хватает. Дополнительный [шлюз (gateway)](gateway/README.md) обслуживает несколько аккаунтов Google через три инструмента.

Оба сервера говорят с Google через клиент, который вы создаёте в собственном проекте Google Cloud, так что между вами и Google нет посредника.

## Что это даёт

Поручите Claude целую работу, которая проходит через несколько приложений Google, обычными словами:

```
Проверь почту: нет ли чего от клиента. Если прислали презентацию, прочитай её и их комментарии, пересобери в нашем стиле с финансовой моделью, положи модель в таблицу, с которой они смогут работать, отправь всё обратно, поставь время, чтобы это обсудить, а потом дай мне аналитику за неделю.
```

Claude находит письмо и сохраняет вложенную презентацию, читает комментарии в их Slides, пересобирает презентацию на вашем компьютере, загружает её обратно как Slides и кладёт рядом PDF, строит модель в Sheets с живыми формулами и даёт к ней доступ, правит их бриф прямо в документе и закрывает комментарии, отвечает в той же переписке с PDF и ссылками, ставит час со ссылкой на Meet и записывает аналитику за неделю в Doc. В [docs/08-uses.md](docs/08-uses.md) эта работа разобрана по шагам: какой инструмент стоит за каждым шагом и что он меняет.
## Сколько это стоит

Денег не нужно. На страницах лимитов Google для Gmail, Drive, Calendar, Docs, Sheets, Slides и Forms API сказано, что обычное использование «is available at no additional cost», то есть без дополнительной платы (прочитано 2026-10-05). Analytics Data API считает работу в «токенах» на ресурс: 200 000 в день для обычного ресурса, и цены на его странице квот нет. Проекту не нужен платёжный аккаунт, карту вы не привязываете.

Платить приходится другим, и это стоит знать заранее:

- **Около 25 минут**, один раз, в основном в консоли Google.
- **Ограничения Google для личного приложения.** Если оставить приложение в режиме Testing, Google будет завершать ваш вход каждые 7 дней. Если опубликовать его без проверки Google, при входе вы увидите предупреждение, а пользоваться приложением смогут не больше 100 человек за всё время. Вы один человек, так что публикация выгоднее. Обе ситуации разобраны в [docs/03-consent.md](docs/03-consent.md).
- **То, что читает Claude.** Серверы отправляют ваши данные только в API Google. Но всё, что Claude прочитал через них, например текст письма, попадает в разговор с Claude Code, как любой файл, который он открывает. Что это значит, описано в [SECURITY.md](SECURITY.md).

## Первые 25 минут

Нужны git, Python 3.10 или новее и [Claude Code](https://code.claude.com/docs/en/overview). Затем в терминале:

```
git clone https://github.com/block-town/google-doors
cd google-doors
claude
```

Когда откроется Claude Code, напишите:

```
Set me up.
```

Можно и по-русски: «Настрой меня». Claude говорит, что собирается сделать, и даёт первую ссылку на консоль Google. Весь путь описан для него в [CLAUDE.md](CLAUDE.md):

- Он ведёт вас по шагам Google по одной странице: кликаете вы, а он сверяет то, что вы видите, со страницей руководства.
- Он запускает `./setup --dry-run` и показывает все изменения, которые настройка внесёт на ваш компьютер, и ждёт вашего «да».
- Он спрашивает, куда вы сохранили файл клиента, который дал вам Google ([docs/04-client.md](docs/04-client.md)), и ваш адрес Google, и запускает `./setup` с этим путём. Файл читает сам скрипт: секрет никогда не проходит через чат, и Claude никогда не открывает ни этот файл, ни конфиг, куда он попадает. Нет файла? Тогда вы запускаете `./setup` в своём терминале и вводите значения там, они не видны при вводе.
- Он запускает два входа. Браузер каждый раз открывает страницу Google, и вы соглашаетесь.
- Он запускает `./doctor`, зачитывает вам результат и говорит, что исправить, если нужно.

Перед каждой командой Claude Code спрашивает разрешения. Прочитайте команду, потом подтвердите. **Если что-то не так,** Claude покажет ошибку и страницу, где она разобрана; все ошибки, которые знает kit, собраны в [docs/10-trouble.md](docs/10-trouble.md).

Проверено на macOS: `./setup`, `./auth`, `./auth-analytics` и `./doctor`, и при ручном вводе, и в том режиме, в каком их запускает Claude. Каждая страница про консоль Google берёт подписи из собственного руководства Google и называет дату, когда его читали. На Linux всё должно работать так же; на Windows используйте WSL.

## Своими руками

Тот же путь, только без Claude за рулём, по странице на шаг. По консоли Google вы в любом случае кликаете сами: никакая программа не создаст ваш проект Google Cloud без вашего входа.

1. [Создайте проект Google Cloud](docs/01-project.md), около трёх минут: коробка, в которой Google считает вызовы вашей программы.
2. [Включите API Google](docs/02-apis.md): одна ссылка включает все тринадцать, включая два API для Analytics.
3. [Настройте экран согласия](docs/03-consent.md), около пяти минут, и опубликуйте приложение: в статусе Testing Google завершает ваш вход каждые 7 дней.
4. [Создайте клиент](docs/04-client.md) и скачайте JSON-файл, который предлагает Google: setup читает клиент из него.
5. Включите свой личный переключатель Apps Script API на [script.google.com/home/usersettings](https://script.google.com/home/usersettings). В аккаунте Workspace администратору может понадобиться отметить клиент как доверенный: в [docs/05-admin.md](docs/05-admin.md) есть все нажатия и текст письма администратору.
6. Запустите `./setup` ([docs/06-install.md](docs/06-install.md)). Если у вас нет uv, он его поставит, затем поставит оба сервера, спросит путь к файлу клиента и ваш адрес Google, запишет их в файл, который можете читать только вы, и добавит оба сервера в Claude Code. Потом он дважды проведёт вход в Google: один раз для приложений Workspace, второй только для Analytics ([docs/07-first-call.md](docs/07-first-call.md)). План без изменений: `./setup --dry-run`; без Analytics: `./setup --no-analytics`.
7. Запустите `./doctor`. По одному вызову на чтение в каждый сервис; в каждой строке должно быть `ok`, любое другое слово называет исправление.
8. Откройте новую сессию Claude Code в любой папке и спросите: `Покажи темы и отправителей пяти моих самых новых непрочитанных писем. Ничего не меняй.` Claude вызовет `search_gmail_messages` и ответит списком ваших писем. Потом попробуйте целую работу из [docs/08-uses.md](docs/08-uses.md).

## Дальше, каждый день

| Вы вводите | Что происходит |
|---|---|
| `./doctor` | проверяет установку, вход и каждый сервис и называет, что не так |
| `./auth` | входит заново, когда Google завершил вход или вы поменяли набор сервисов |
| `./auth-analytics` | то же для входа в Analytics |
| `./setup --account work` | добавляет второй аккаунт Google ([docs/09-several-accounts.md](docs/09-several-accounts.md)) |
| `./setup --gateway` | обслуживает все ваши аккаунты через три инструмента ([gateway/README.md](gateway/README.md)) |

## Как уйти

1. Уберите серверы из Claude Code: `claude mcp remove google -s user` и `claude mcp remove analytics -s user` (и `google-<имя>`, `analytics-<имя>` для каждого дополнительного аккаунта).
2. Удалите программы серверов: `uv tool uninstall workspace-mcp analytics-mcp`.
3. Удалите клиент и токены: `rm -r ~/.config/google-doors`.
4. Отзовите доступ приложения в аккаунте Google: [myaccount.google.com/linkedapps](https://myaccount.google.com/linkedapps), выберите приложение, затем Remove access.
5. Удалите эту папку.

Каждый шаг объяснён в [SECURITY.md](SECURITY.md).
